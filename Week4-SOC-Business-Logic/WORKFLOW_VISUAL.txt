╚══════════════════════════════════════════════════════════════════════════════════════════════════════════╝

🔴 DETECTION (What we learned):
   ├─ You can detect attacks by finding patterns in logs
   ├─ 7 detection rules catch most price/qty manipulation attacks
   ├─ Rules need tuning to avoid false positives
   └─ Detection takes seconds; investigation takes hours

🟡 TRIAGE (What we learned):
   ├─ Most alerts are false positives (95%+)
   ├─ Real attacks need careful validation before escalation
   ├─ Behavioral context matters (is this user normal?)
   └─ Decision trees reduce alert fatigue

🟢 RESPONSE (What we learned):
   ├─ Speed is critical: Block within 15 min, reverse within 30 min
   ├─ Communication is essential: Keep stakeholders updated
   ├─ Root cause matters: Fix the code, not just the symptoms
   └─ Process matters: Follow playbook to avoid mistakes


╔══════════════════════════════════════════════════════════════════════════════════════════════════════════╗
║                                  🎯 DETECTION RULES AT A GLANCE                                         ║
╚══════════════════════════════════════════════════════════════════════════════════════════════════════════╝

Rule 1: NEGATIVE QUANTITY       → if qty < 0 → CRITICAL        Refund abuse
Rule 2: NEGATIVE PRICE          → if price < 0 → CRITICAL      Payment fraud
Rule 3: PRICE MANIPULATION      → if variance > 10% → CRITICAL  MITM attack
Rule 4: QUANTITY-PRICE MISMATCH → if calc error > 5% → CRITICAL Cart manipulation
Rule 5: EXTREME DISCOUNT        → if discount > 80% → HIGH      Code enumeration
Rule 6: TOTAL CALCULATION ERROR → if math ≠ expected → HIGH    Rounding abuse
Rule 7: ANOMALY FLAGS          → if RISK/ANOMALY in log → VAR   Upstream detection
